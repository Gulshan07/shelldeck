Shelldeck — how to use it

  
A connection manager that runs in your browser but talks only to your own machine.
    Everything you save is encrypted on your computer and shared with no one.


  

    
1. Unlock

    
On first launch you set a master password. It encrypts everything — server passwords,
    keys, VPN details. You enter it once per session; the vault re-locks after 15 minutes idle
    (open sessions keep running). Change it any time with Change password (bottom left).

  


  

    
2. Add servers

    

      
+ (top of the list)add a connection: name, host, user, and either a
        password or a private key (paste it or pick the file)

      
Import (download icon)pull in everything from ~/.ssh/config or Ásbrú at
        once — grouped, with jump hosts linked. Passwords are never read; you review a preview first.

      
pencil / bin on a rowedit or delete a connection

      
Protocol (in the editor)SSH (default) · Telnet for
        network gear — host and port only, no key or user · Serial for a console cable —
        give it the device (e.g. /dev/ttyUSB0) and baud rate instead of a host. The form
        shows only the fields that protocol needs. Logging and macros work on all three.

      
Export… (in Import)saves a JSON file of your connections, groups, jump
        links and forwarding rules to hand to a colleague. It contains no passwords, keys,
        passphrases, TOTP secrets, VPN profiles or macro bodies — only the key-file paths, so
        they know which key each host needs.

      
Shared file (in Import)imports a colleague's exported file. Jump hosts
        are re-linked by name, duplicates are skipped, and you review a preview first. Each person
        adds their own passwords and keys afterwards.

    

  


  

    
3. Connect

    

      
Click a connectionopens a terminal in a new tab

      
Ctrl + clickopens it beside the current one (split view)

      
folder icon on a rowopens a file browser (SFTP) instead of a terminal

      
grid icon on a row (Alt+I)starts 2 to 7
        instances of the same host, side by side in one tab — turn on broadcast and you
        have several shells on one box taking the same input. More than 7 leaves the panes too
        narrow to read.

      
First time to a hostyou confirm its fingerprint once, then it's trusted

      
a small bolt next to a namethat connection runs a macro automatically
        when it opens (see Automation below)

      
a key owned by rootyou are asked for your sudo password once, the
        key is then cached encrypted and never asked for again

    

  


  

    
4. Organise

    

      
Drag a connection onto a groupmoves it into that group

      
copy button on a connectionclones it into the same group as
        name-1, keeping its password or key, then opens the copy for editing —
        the quick way to add the next box in a fleet. Press Esc to keep the
        suggested name.

      
Click a group headercollapse or expand it

      
Search boxmatches name, host/IP, username, group, protocol, port and
        the jump host's name. Several words narrow it further — star db finds db hosts
        in the STAR group.

      
Drag the sidebar's right edgemake the list wider or narrower (double-click the edge to reset)

      
Tab / Enterthe whole list is keyboard-navigable — Tab to a
        connection and press Enter to open it (Ctrl+Enter to split)

      
sun / moon (top right)switch the whole app between light and dark

    

  


  

    
5. Jump hosts (bastions)

    
Add the bastion as its own connection, then set it as the target's Jump host in the
    editor. Shelldeck connects through it automatically. Chains work (jump through a jump), and
    every hop's key is checked.

  


  

    
6. Automation: macros & broadcast

    
Attach macros to a server: in a connection's editor, open "Macros for this connection",
    tick the macros it should offer, and optionally pick one to run on connect — so opening
    that server can log you straight into mysql, sudo to root, etc. (like Ásbrú's Expect &
    Execute). A server's own macros are what its bolt button lists.

    
Fastest way: hover a group header and click the grid button to open every server in that
    group side by side in one tab. (Or open them yourself with Ctrl-click.) Then click
    broadcast in the tab bar — now what you type goes to every terminal in that
    tab at once, so one command runs across the whole fleet. Broadcasting panes get a red outline so
    you always know it's on. Click it again to stop.

  


  

    
7. Files (SFTP)

    

      
Click a folder / fileopen it / download it

      
filter boxtype to filter this folder; press Enter to search the
        whole server below it

      
uploadsend one or more files into the current folder

    

  


  

    
8. Port forwarding

    
In a connection's editor, one rule per line. Starts with the session, stops when you close it.
    Listeners are local-only (127.0.0.1).

    
L 8080:localhost:80     reach the server's :80 at your localhost:8080
R 9090:localhost:22     expose your :22 to the server as :9090
D 1080                  a SOCKS proxy on your localhost:1080

  


  

    
9. VPN (one click, password + code automatic)

    
Add a VPN profile with + next to VPN: pick your .ovpn file, enter the
    username, password and your authenticator secret (the base32 setup string, not the 6-digit
    code). Then connect — the code is generated and answered for you. A green dot shows it's up
    with the assigned IP; the list button shows the log. Needs OpenVPN installed
    (sudo apt install openvpn).

  


  

    
10. Session logs

    
Tick Record an encrypted session log in a connection's editor to save everything that
    happens in its terminal. Logs are encrypted with your vault (they can contain passwords typed on
    screen), and the document button in the sidebar lists, opens and deletes them.

    

      
open on a logdecrypts it and shows the whole session as text

      
Play recordingreplays the session in a terminal at the speed it
        originally happened — the timing of every chunk is stored, so it plays back like a recording
        rather than a dump. Long idle gaps are shortened so it stays watchable.

      
Speed 1×–8×fast-forward the replay

      
deleteremoves that log permanently

    

    
Logs live in ~/.shelldeck/logs/*.eclog, capped at 50 MB per
    session. They are only readable while your vault is unlocked.

What stays private

    
    
      
  • The server only listens on your own machine (127.0.0.1) — nothing is exposed to the network.
    • 
      
  • Passwords, keys, VPN details and logs are encrypted in ~/.shelldeck;
        hostnames and ports sit in plain config with no secrets.
    • 
      
  • Secrets never reach the browser — the page asks to connect, the server does the login.
    • 
      
  • A root-owned key file is read once via sudo (asked when needed) and cached
        encrypted; the sudo password is never stored.
