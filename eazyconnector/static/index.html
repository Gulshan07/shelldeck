EazyConnector — how to use it

  
A connection manager that runs in your browser but talks only to your own machine.
    Everything you save is encrypted on your computer and shared with no one.


  

    
1. Unlock

    
On first launch you set a master password. It encrypts everything — server passwords,
    keys, VPN details. You enter it once per session; the vault re-locks after 15 minutes idle
    (open sessions keep running). Change it any time with Change password (bottom left).

  


  

    
2. Add servers

    

      
+ (top of the list)add a connection: name, host, user, and either a
        password or a private key (paste it or pick the file)

      
⇩ importpull in everything from ~/.ssh/config or Ásbrú at
        once — grouped, with jump hosts linked. Passwords are never read; you review a preview first.

      
✎ / ✕edit or delete a connection

    

  


  

    
3. Connect

    

      
Click a connectionopens a terminal in a new tab

      
Ctrl + clickopens it beside the current one (split view)

      
🗁 iconopens a file browser (SFTP) instead of a terminal

      
First time to a hostyou confirm its fingerprint once, then it's trusted

    

  


  

    
4. Organise

    

      
Drag a connection onto a groupmoves it into that group

      
Click a group headercollapse or expand it

      
Search boxfilter the whole list as you type

      
Drag the sidebar's right edgemake the list wider or narrower (double-click the edge to reset)

    

  


  

    
5. Jump hosts (bastions)

    
Add the bastion as its own connection, then set it as the target's Jump host in the
    editor. EazyConnector connects through it automatically. Chains work (jump through a jump), and
    every hop's key is checked.

  


  

    
6. Broadcast to many servers (clusters)

    
Fastest way: hover a group header and click ◫ to open every server in that
    group side by side in one tab. (Or open them yourself with Ctrl-click.) Then click
    ⇄ broadcast in the tab bar — now what you type goes to every terminal in that
    tab at once, so one command runs across the whole fleet. Broadcasting panes get a red outline so
    you always know it's on. Click it again to stop.

  


  

    
7. Files (SFTP)

    

      
Click a folder / fileopen it / download it

      
filter boxtype to filter this folder; press Enter to search the
        whole server below it

      
uploadsend one or more files into the current folder

    

  


  

    
8. Port forwarding

    
In a connection's editor, one rule per line. Starts with the session, stops when you close it.
    Listeners are local-only (127.0.0.1).

    
L 8080:localhost:80     reach the server's :80 at your localhost:8080
R 9090:localhost:22     expose your :22 to the server as :9090
D 1080                  a SOCKS proxy on your localhost:1080

  


  

    
9. VPN (one click, password + code automatic)

    
Add a VPN profile with + next to VPN: pick your .ovpn file, enter the
    username, password and your authenticator secret (the base32 setup string, not the 6-digit
    code). Then connect — the code is generated and answered for you. A green dot shows it's up
    with the assigned IP; ☰ shows the log. Needs OpenVPN installed
    (sudo apt install openvpn).

  


  

    
10. Session logs

    
Tick Record an encrypted session log in a connection's editor to save everything that
    happens in its terminal. Logs are encrypted with your vault (they can contain passwords typed on
    screen), and the 📜 button lists, opens and deletes them.

  


  

    
11. Advanced & appearance

    

      
Editor → Advancedrun a command locally before connecting, a command on the
        server right after login, a command locally after disconnecting; set the keepalive interval

      
⚙ (top of the list)terminal theme, font size and family

What stays private

    
    
      
  • The server only listens on your own machine (127.0.0.1) — nothing is exposed to the network.
    • 
      
  • Passwords, keys, VPN details and logs are encrypted in ~/.eazyconnector;
        hostnames and ports sit in plain config with no secrets.
    • 
      
  • Secrets never reach the browser — the page asks to connect, the server does the login.
    • 
      
  • A root-owned key file is read once via sudo (asked when needed) and cached
        encrypted; the sudo password is never stored.
